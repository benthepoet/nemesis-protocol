# AGENTS.md — Assets

Conventions for everything under `assets/`. Applies to all agents producing or touching asset files.

## Tooling

- **Blender MCP** is available for 3D modeling and is Kimi's tool of record — with a judgment rule: hero/complex assets (ship exterior, weapons, androids, bosses) warrant it; blockout geometry, simple props, and 2D-derived assets use lighter paths. Don't open Blender for what a primitive kit-bash solves.
- **Export standard:** models ship as **glTF/GLB** with standard PBR maps (PNG/WebP; KTX2 for hero sets) — the three.js pipeline per `docs/design/visual_direction.md` §8.
- **License compatibility:** all shipped assets are licensed CC BY 4.0 (`LICENSE-ASSETS`) and must be original or built from CC0/CC BY sources with attribution logged. **Web reference images are inspiration only — never shipped, never committed** (see Reference-first rule for the index/cleared exceptions). Enforcement: `references/` image files are gitignored and excluded from builds and releases, and Kimi's Gate 1 includes a license scan (charter §3 Stage 5).
- **Reference-first rule:** before generating any tangible asset (ships, weapons, props, characters), gather a reference board — 4–8 web reference images covering silhouette, materials, and lighting. **Commit policy (public repo):** commit only the `references.md` index (links + notes + attribution). Third-party copyrighted image files are **never committed or shipped** — gitignored, local-only. License-clean images (CC0 / CC BY / public domain) may be committed under `references/cleared/` with attribution logged. Boards are cited in the design pack. No reference board, no generation.

## Rules

1. **Never hand-edit generated mockups.** The SVGs in `assets/mockups/` are generated by scripts in `tools/mockups/`. Change the script, regenerate, commit both.
   - Deck plan: `python3 tools/mockups/gen_ship_svg.py` → `assets/mockups/cruiser_boarding_deck_plan.svg`
   - Mission flow overlay: `python3 tools/mockups/gen_flow_svg.py` → `assets/mockups/cruiser_mission_flow_overlay.svg`
2. **Version linkage:** mockup subtitles carry a version tied to the design doc (deck plan currently v2.2; flow overlay is a companion to design doc v1.6). When a design change affects a mockup, bump the mockup version in the same commit as the doc change.
3. **Naming:** human-readable, phase-prefixed for game assets (e.g., `p1_android_rack_diffuse.png`); schematic/mockup files keep snake_case descriptive names.
4. **Kimi K3 owns visual quality and consistency** (charter §1). The binding standard is `docs/design/visual_direction.md` — palette (§3), ship-state lighting matrix (§4), materials (§5), and readability rules (§7). New assets must conform; deviations require a version bump there.
5. **Preview:** `app/` is a generated HTML wrapper around the mockups for browser preview — regenerate it from the SVGs; don't edit it by hand.
